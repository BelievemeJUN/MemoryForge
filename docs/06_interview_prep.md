> 构建"自然语言 → 自动写代码 → 隔离沙箱执行 → 按测试自愈"的 Agent：手写 LangGraph 状态机（弃用 create_agent），重试预算硬熔断；沙箱六层纵深防御（断网/只读/非root/seccomp/资源配额/digest 白名单）+ 分布式并发 + 审计落库。生产化：API Key 认证 + 多租户配额、Redis 滑动窗口限流、per-user token 成本熔断、request_id 全链可观测、GitHub Actions CI（45 用例 + 安全回归全绿）。

### 详细版（5 行，面试官深挖的索引）
- **执行引擎**：LangGraph 手写总图（意图判断→chat/exec/read）；exec 子图 plan→write→execute→verify→fix 自愈循环 + 硬熔断，确定性比对（exact/fuzzy/float）。
- **沙箱安全**：六层防御（断网/rootfs 只读/非 root/cap_drop/seccomp/资源配额）+ AST 静态审查 + 镜像白名单&digest 锁定 + Redis 分布式并发 + 孤儿回收 + 审计落库；11 个攻击用例全绿。模板镜像预装 numpy/pandas；可选联网走白名单代理。
- **记忆**：四类记忆（摘要/语义/情节/程序）+ Milvus 混合检索（向量+BM25+RRF）+ 后台异步提取 + 全场景注入；访问时间 Redis 节流 + 低频低价值自动淘汰。
- **生产化**：认证（不信请求参数）、多租户配额、Redis 限流、per-user 成本熔断与可见性、PostgreSQL 会话隔离、request_id + JSON 日志 + 四依赖健康探活。
- **质量**：pytest 45 用例 + 安全回归自动化 + GitHub Actions CI；Dockerfile + docker-compose 生产编排 + 密钥治理。

> "我做了一个**能真正动手的对话 Agent**：用户说'用 Python 算 1 加到 100'，它不是背答案，而是走一遍**规划→写码→隔离沙箱运行→拿真实输出→不过测试就自愈重写**，把真实执行结果返回给你。

## 3. 高频追问 + 三层答法

**框架：先给结论（一句话）→ 再给细节（怎么做的）→ 最后给数据/权衡（证明不是吹的）。**

### Q1. 这个项目最大的难点是什么？
- **结论**：让 AI 生成的不安全代码，在一个"几乎什么都干不了"的容器里安全运行。
- **细节**：六层防御——断网、rootfs 只读、非 root、cap_drop 去能力、自定义 seccomp（禁逃逸 syscall）、资源配额；再加容器前的 AST 静态审查做"友好拦截"。
- **数据/权衡**：11 个攻击用例（rm -rf、反弹 shell、读 shadow、fork 炸弹、无限内存、写满磁盘）全绿。诚实补充：容器共享宿主内核，逃逸边界存在，生产应上 VM 级隔离（gVisor/Kata）——**主动讲边界反而加分**。

### Q2. 为什么不用现成的 Agent 框架（如 LangGraph 的 create_agent / AutoGPT）？
- **结论**：黑盒不可控、不可测、不可预算。
- **细节**：我手写状态机——意图判断是显式节点、执行是嵌套子图、失败走 verify→fix 循环；每一步的 token 都在记账。
- **数据/权衡**：自愈评测：单次通过率 27% → 自愈后 100%；熔断保证不无限烧钱。黑盒做不到这种粒度控制。

### Q3. 代码执行失败了怎么办？
- **结论**：确定性验证 + 修复循环 + 硬熔断，绝不无限重试。
- **细节**：写码 → 沙箱跑 → 用 hidden test 的确定性比对（exact/fuzzy/float）判断对错，失败把报错喂回 LLM 修，重试次数是状态机硬编码的。
- **数据/权衡**：硬计数是防"AI 不自量力"的关键——软约束会被模型无视。评测里从 27% 提到 100%。

### Q4. 怎么防用户恶意使用（烧钱 / 打爆资源）？
- **结论**：身份 + 配额 + 限流 + 成本熔断四道闸。
- **细节**：API Key 认证（user_id 只信认证上下文，不信请求参数）→ 多租户沙箱配额（每用户内存/pids 可配）→ Redis 滑动窗口限流（IP+用户双层）→ per-user 每日 token 预算超限熔断；沙箱还有全局+每用户分布式并发上限。
- **数据/权衡**：实测伪造 user_id 会 401、超预算返回 429；成本按日清零。

### Q5. AI 会"忘记"用户吗？
- **结论**：四类记忆 + 混合检索 + 全场景注入，记得住。
- **细节**：摘要/语义/情节/程序四类记忆存 Milvus，向量+BM25 混合检索 RRF 融合；对话后后台异步提取，普通对话也注入记忆（不只等用户问）；程序记忆让写码符合用户偏好。
- **数据/权衡**：修过一个真实 bug——Milvus upsert 要全字段（含向量），像剥洋葱一个个暴露，最后全字段带齐一次解决；还用 Redis 节流把写放大降一个数量级。

### Q6. 上线后怎么排查问题？
- **结论**：一个 request_id 贯穿一条请求。
- **细节**：每个请求自动生成/透传 request_id，进日志、出响应头；JSON 单行日志；/health 并行探活四个依赖（PG/Redis/Milvus/Docker）。
- **数据/权衡**：踩过"健康探活用缓存连接会跨事件循环报错"，改用一次性连接。

### Q7. 怎么保证质量？
- **结论**：提交即验证——CI 全自动。
- **细节**：pytest 45 用例（单元+集成）+ 安全回归自动化（攻击用例动态生成测试）+ GitHub Actions（lint/单元/集成，PG/Redis 用 services）。
- **数据/权衡**：CI 修过一个真坑——漏装 requirements-sandbox.txt 导致 docker SDK 缺失，全红到全绿。这也说明 CI 是真的在拦问题。

### Q8. 沙箱怎么做到"能联网又不危险"？
- **结论**：默认断网；联网是可选模式，走白名单代理。
- **细节**：SANDBOX_NETWORK=proxy 时沙箱接入受限网络，所有出站经一个域名白名单代理（CONNECT），非白名单直接 403 并留日志。
- **数据/权衡**：实测白名单域名隧道通、evil.com 被拒。诚实讲：这是应用层白名单，强制白名单要网络层防火墙，生产会叠加。

### Q9. 多租户怎么隔离？
- **结论**：数据 + 资源 + 身份三层隔离。
- **细节**：Milvus 按 user_id 分区；Redis 任务 key 带用户前缀（task:42:*）；沙箱配额按用户解析；API Key 决定你是谁。
- **数据/权衡**：实测 user42 容器拿到 128MiB/32pids，user7 看不见 user42 的任务。
